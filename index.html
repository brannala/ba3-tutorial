ConGen 2026 · 30-minute hands-on tutorial · simulated and real SNP datasets

Plan

0. Set up 2 min

BA3 runs in a terminal: on the course server, the RStudio Terminal tab. The two R steps (a trace plot and an ancestry table) run in the RStudio Console. In the terminal, copy the tutorial folder, set two variables and move to the run directory:

cp -r ~/instructor_materials/Bruce_Rannala/ba3_tutorial ~/
D=~/ba3_tutorial/data
mkdir -p ~/ba3_tutorial/runs && cd ~/ba3_tutorial/runs

All runs are made in this one directory. Each run gets a name with -r, which BA3 puts in front of every file it writes: -r demo8 -o out.txt writes demo8_out.txt and, if asked for, demo8_BA3trace.txt and demo8_BA3indiv.txt.

1. A dataset with a known truth 7 min

demo8: 8 populations of 513–582 individuals (4,383 in total), 2,000 unlinked SNPs, FST = 0.05, no inbreeding, no missing data. It was simulated under BA3's own model with three migration routes: pop0 → pop1 (m = 0.15), pop2 → pop3 (0.10) and pop4 → pop5 (0.05). Every other route has no migration. The file data/demo8_truth.json records the true ancestry of every individual.

Run BA3 (about 1 min)

BA3 -c -H -e 1000 -s 1 -i 600000 -b 250000 -n 25 -r demo8 \
     -V $D/demo8.vcf -M $D/demo8_meta.txt -o out.txt
OptionMeaning
-V, -Mthe VCF, and a two-column file of individual and population
-ccollapsed sampler: allele frequencies are integrated out, which is much faster and targets the same posterior
-Hhierarchical allele-frequency prior: population frequencies vary around shared ancestral frequencies
-i, -b, -niterations, burn-in, and sampling interval (here 14,000 states are recorded after burn-in)
-srandom-number seed
-ewrite the trace (demo8_BA3trace.txt) every 1,000 iterations. Each trace line recomputes the full log-likelihood, so a trace at every recorded state (-t) would add about 40 s here
-rrun name, put in front of every output file
-othe results file (demo8_out.txt with the run name)

With many individuals, BA3 needs more iterations: each iteration updates only part of the state, so with 4,383 individuals each one is visited less often. Question 4 shows what happens during burn-in.

Look at the results

grep -A 11 "Migration Rate" demo8_out.txt       # migration matrix
grep "for H1" demo8_out.txt                      # routes with evidence of migration
grep -A 5 "Pr(c=0) =" demo8_out.txt              # notes under the Bayes-factor table

Read the matrix as row i = the population sampled, column j = the source: m[1][0] is the fraction of pop1 descended from migrants from pop0. Each row sums to 1.

  1. Which routes have m clearly above the background? How close are the estimates to the simulated values 0.15, 0.10 and 0.05?
    Answerpop0 → pop1 = 0.156, pop2 → pop3 = 0.107, pop4 → pop5 = 0.035 (SD 0.004–0.007); every other off-diagonal entry is about 0.0006. The estimates match the migrants actually sampled: 256 of the 540 individuals in pop1, 184 of 565 in pop3 and 54 of 513 in pop5 are migrants, which correspond to m = 0.158, 0.109 and 0.035. pop5 happens to contain fewer migrants than the simulated rate predicts. BA3 estimates migration in your sample; the gap to the simulation parameter is binomial sampling noise that more loci cannot remove.
  2. The Bayes-factor table reports BF01 for every route. BF01 > 1 supports no migration, < 1 supports migration. How strong is the evidence on the three true routes, and on the 53 absent ones? What does the < in front of some Bayes factors mean?
    AnswerAll three true routes are "Decisive for H1", printed as <0.0056 or similar. BA3 estimates Pr(c = 0) by the fraction of recorded states with no migrants on the route, and here none of the 14,000 states had any. The < value is what a single such state would give: it shows the resolution of the run, not a guaranteed bound, and it would change with a longer run. Exercise 2 uses -B to estimate the Bayes factor on such routes. All 53 absent routes are "Strong for H0", and none is "Decisive".
  3. Why can't any absent route reach "Decisive for H0" (BF01 > 100)?
    AnswerBF01 = Pr(c = 0 | data) × (ni + K − 1)/(K − 1), where c is the number of sampled individuals that are migrants on the route, ni is the sample size of the receiving population and K the number of populations. Here Pr(c = 0) = 1.0000 on every absent route, so the Bayes factor is already at its ceiling: (513 + 7)/7 = 74.3 to (582 + 7)/7 = 84.1. Finding no migrants among n individuals cannot exclude a small rate, so only more individuals, not more loci, raise the ceiling. With K = 8, decisive evidence needs ni > 99 × 7 = 693. (Exercise 2 shows the effect of fewer populations.)
  4. Did the run converge? Run a second seed (about 1 min) and compare the two matrices: 
    BA3 -c -H -s 2 -i 600000 -b 250000 -n 25 -r demo8_s2 \
     -V $D/demo8.vcf -M $D/demo8_meta.txt -o out.txt
grep -A 11 "Migration Rate" demo8_out.txt demo8_s2_out.txt
    Then plot the trace of the first run in the RStudio Console; the plot appears in the Plots pane. The trace starts at the beginning of the run, so it includes the burn-in; the dashed line marks its end: 
    source("~/ba3_tutorial/scripts/plot_trace.R")
plot_trace("~/ba3_tutorial/runs/demo8_BA3trace.txt", "m[1][0]", burnin = 250000)

    Without RStudio, run Rscript ~/ba3_tutorial/scripts/plot_trace.R demo8_BA3trace.txt "m[1][0]" 250000 demo8_trace.png in the terminal and open the PNG file.

    AnswerThe two seeds agree to within about 0.001. The trace shows why the burn-in matters: m[1][0] starts near 0.02 and climbs to about 0.15 over the first 200,000–250,000 iterations while the log probability rises, then both fluctuate around a stable level. A run of 200,000 iterations would have stopped while the chain was still climbing and reported m ≈ 0.11. Agreement between seeds is necessary but not sufficient: a chain can settle in the same wrong mode with every seed (Exercise 4). Compare runs of different lengths too.

2. Who are the migrants? 5 min

demo3: 3 populations of 315–337 individuals, 1,000 SNPs, FST = 0.05. pop1 receives migrants from two sources: pop0 (m = 0.10) and pop2 (0.05). Two new options:

  • -g writes, for every individual, the posterior probability of each ancestry to demo3_BA3indiv.txt. That file lists each individual's genotypes too, so it grows with individuals × loci (12 MB here); use -g only when you need it.
  • -B 10 adds a second Bayes-factor table, computed from every 10th recorded state, that estimates the Bayes factor even on routes where the default table can only print <. It is slower (it computes every individual's likelihood under every ancestry), so use it when < appears on a route that matters.

Run BA3 (about 20 s)

BA3 -c -H -g -B 10 -s 1 -i 300000 -b 100000 -n 50 -r demo3 \
     -V $D/demo3.vcf -M $D/demo3_meta.txt -o out.txt

Look at the results

grep -A 6 "Migration Rate" demo3_out.txt
grep -A 10 "Savage-Dickey Density" demo3_out.txt
grep -A 12 "Exact Savage-Dickey" demo3_out.txt
grep -A 200 "Individual: p1_012 " demo3_BA3indiv.txt | grep -A 3 "Migrant ancestry"

In demo3_BA3indiv.txt, [s,g] is the probability that the individual's ancestry is from population s with generation g: 0 = non-migrant, 1 = first-generation migrant, 2 = child of a migrant.

  1. How well are the two migration rates into pop1 estimated? How strong is the evidence that the other four routes are absent, and why is it stronger than in Exercise 1?
    Answerm = 0.107 from pop0 and 0.050 from pop2, matching the migrants sampled (0.107 and 0.050). The four absent routes are "Decisive for H0", with BF01 = 158 (into pop0) and 168 (into pop2). Those are the ceilings, (ni + K − 1)/(K − 1) = (ni + 2)/2 for 315 and 334 individuals: no sampled individual is a migrant on these routes. In Exercise 1 the populations were larger (513–582 individuals), yet the ceiling was only 74–84, because there K − 1 = 7 instead of 2. With more populations, the prior spreads each population's migrants over more possible sources, so every single route already has a small rate a priori, and finding no migrants on it is weaker evidence.
  2. The default table prints the two true routes as <0.0424, "Strong for H1 or more". What does the -B table give, and why can the default table not show it?
    Answerlog10 BF01 ≈ −1,916 for pop0 → pop1 and −895 for pop2 → pop1: overwhelming evidence for migration. The default table counts recorded states with no migrant on the route; with 4,000 states and none of them having c = 0, the smallest value it can show is about 1/4,000 of the ceiling, 0.04. -B averages, over the states, the probability that no individual is a migrant from the source given the state's migration rates and allele frequencies, which is never exactly zero. The last digits of such extreme values vary between runs, which does not matter this far from any threshold. On the absent routes both tables agree (BF01 = 158 and 168).
  3. What is individual p1_012?
    Answer[2,2]:1.000: the child of a migrant from pop2 (a second-generation migrant), with probability 1. The truth file agrees: grep p1_012 ~/ba3_tutorial/data/demo3_truth.tsv.
  4. How many individuals in pop1 does BA3 classify correctly? In the RStudio Console, find each individual's most probable ancestry and tabulate it against the truth: 
    source("~/ba3_tutorial/scripts/ancestry_vs_truth.R")
ancestry_vs_truth("~/ba3_tutorial/runs/demo3_BA3indiv.txt",
                  "~/ba3_tutorial/data/demo3_truth.tsv", pop = "pop1")

    Without RStudio: Rscript ~/ba3_tutorial/scripts/ancestry_vs_truth.R demo3_BA3indiv.txt ~/ba3_tutorial/data/demo3_truth.tsv pop1 in the terminal.

    AnswerAll 337: every count is on the diagonal (179 non-migrants; 36 first- and 72 second-generation migrants from pop0; 19 and 31 from pop2), and every individual's most probable ancestry has probability 1. With 1,000 SNPs at FST = 0.05, each migrant is unambiguous, generation included. With lower differentiation or fewer loci the probabilities spread out, and individuals are no longer classified with certainty.

3. One population sampled as two 3 min

split: 4 simulated populations (50, 100, 50 and 50 individuals; 5,000 SNPs; FST = 0.05) with one true route, pop0 → pop2 (m = 0.1). The 100 individuals of pop1 were divided at random into two "populations", pop1a and pop1b. They are a single randomly mating population.

Run BA3 (about 40 s)

BA3 -c -H -s 1 -i 200000 -b 50000 -n 100 -r split \
     -V $D/split.vcf -M $D/split_meta.txt -o out.txt

Look at the results

grep -A 8 "Migration Rate" split_out.txt
grep "for H1" split_out.txt
grep -A 7 "Inbreeding Coef" split_out.txt
  1. What does BA3 report between pop1a and pop1b? What does the Bayes factor say?
    AnswerMigration in both directions, near the model's upper bound of 1/3: about 0.31 one way and 0.21 the other, both "Decisive for H1". The true route pop0 → pop2 is still recovered (0.10). BA3 has no way to say "these are the same population"; the only way it can explain two samples with the same allele frequencies is to call most of one sample migrants from the other.
  2. How would you recognise this in real data?
    AnswerReciprocal m near 1/3 between a pair of samples; often F ≈ 0.5 with SD ≈ 0.29 in one of them (here pop1b), which is the prior, because almost all its individuals are second-generation migrants and carry no information about F; other routes unaffected. Check pairwise FST, a PCA or STRUCTURE plot and geography, then merge the samples and rerun.

4. Malagasy palms: flat versus hierarchical prior 6 min

palmBN: a published RAD-seq dataset (Dryad 10.5061/dryad.pc866t1z6), 52 individuals from 8 populations (6–7 each), 5,524 SNPs with up to 50% missing data. You run it twice, changing only the allele-frequency prior: first the default flat prior (no -H), then the hierarchical prior. The second run also writes individual ancestries (-g) and the exact Bayes-factor table (-B 1, every recorded state; with only 52 individuals this costs a few seconds).

Run BA3 twice (about 45 s and 60 s)

BA3 -c -s 1 -i 200000 -b 50000 -n 100 -r palmBN_flat \
     -V $D/palmBN.vcf -M $D/palmBN_meta.txt -o out.txt
BA3 -c -H -g -B 1 -s 1 -i 200000 -b 50000 -n 100 -r palmBN_hier \
     -V $D/palmBN.vcf -M $D/palmBN_meta.txt -o out.txt

Look at the results

grep -A 10 "Migration Rate"  palmBN_flat_out.txt palmBN_hier_out.txt
grep -A 10 "Inbreeding Coef" palmBN_flat_out.txt palmBN_hier_out.txt

Population indices: 0 = BN1, 1 = BN2, 2 = BN3, 3 = BN4, 4 = BN5, 5 = BN7, 6 = BN8, 7 = BN9.

  1. Under the flat prior, is there a population that seems to send migrants to many others? What are mii and F in the receiving populations?
    AnswerBN5 (column 4) appears as a source for BN4, BN7, BN8 and BN9, each at m ≈ 0.16–0.17. Those populations have mii ≈ 0.69, close to the lower bound of 2/3, and F ≈ 0.50 with SD ≈ 0.29, which is just the prior on F. Whole populations have been recast as second-generation migrants from BN5. This is the pooling artefact: with few individuals per population, the flat prior lets one population's allele frequencies stand in for several.
  2. What changes with -H?
    AnswerBN5 no longer sends migrants anywhere. Three routes remain: BN2 → BN1 (m ≈ 0.16, found under both priors), BN4 → BN8 (≈ 0.11) and BN3 → BN4 (≈ 0.05, SD 0.03), and the F values (0.00–0.17) are now estimated from the data. With small samples per population, use -H.
  3. The hierarchical run finds evidence for migration on three routes. How strong is it, and how strong can the evidence for no migration be on any route? 
    grep "for H1" palmBN_hier_out.txt        # three lines from the default table, then three from -B
grep "cannot exceed" palmBN_hier_out.txt
    AnswerThe default table prints all three as <0.0013: none of the 1,500 recorded states had zero migrants on them. The -B table gives log10 BF01 ≈ −1,031 (BN2 → BN1), −197 (BN4 → BN8) and −176 (BN3 → BN4). In the other direction, BF01 cannot exceed (7 + 7)/7 = 2.0 with 6–7 individuals per population and K = 8, so all 53 absent routes are only "Weak for H0". Migration is much easier to detect than to exclude: one clearly identified migrant makes the evidence for migration decisive, but no number of loci can show that a route is absent; only sampling many more individuals per population raises that ceiling.
  4. Who are the migrants? List every individual whose most probable ancestry is a migrant ([source,generation], generation 1 or 2): 
    awk '/Individual:/{id=$2} /\[[0-9]+,[12]\]:/{for(i=1;i<=NF;i++){split($i,a,":"); if(a[2]>0.5) print id, a[1], a[2]}}' palmBN_hier_BA3indiv.txt
    AnswerBN3 → BN4 rests on a single individual, BN4_LM244, a second-generation migrant from BN3 with probability 1. One migrant among 7 is enough for decisive evidence of migration, but it leaves m barely estimated (0.05 ± 0.03). The other two routes are different: 6 of the 7 BN1 individuals are called second-generation migrants from BN2, and 4 of the 6 BN8 individuals migrants from BN4. When almost a whole sample is "migrants" from one source, ask whether the two samples are really distinct populations (Exercise 3). The Bayes factor measures the evidence for migration under the BA3 model; it cannot show that the model's explanation is the right one.

5. Sea trout in a Norwegian fjord 7 min

trout: anadromous brown trout (sea trout) from four rivers flowing into Sognefjorden, Norway: Lærdal (29 fish), Årdal (39), Fortun (26) and Aurland (52), typed for 2,138 SNPs with no missing data (Hawley et al. 2025, Evolutionary Applications 18: e70130; data CC0, doi:10.18710/IGV7XU). The populations are declining under hydropower regulation, salmon lice from aquaculture and stocking. The fish are "veteran migrants" caught in the rivers as adults, so the river a fish was caught in is not necessarily the river it was born in. 91 of them also carried acoustic tags, which recorded where they went in the spawning season (data/trout_telemetry.csv).

The published analysis used BA3-SNPs, which has BA3's default flat allele-frequency prior. You run both priors.

Run BA3 twice (about 75 s and 95 s)

BA3 -c -s 1 -i 1000000 -b 250000 -n 100 -r trout_flat -o out.txt $D/trout.txt
BA3 -c -H -g -B 10 -s 1 -i 1000000 -b 250000 -n 100 -r trout_hier -o out.txt $D/trout.txt

This data file is in BA3's own format (individual, population, locus, allele 1, allele 2), so it is given without -V and -M. Population indices: 0 = Lærdal, 1 = Årdal, 2 = Fortun, 3 = Aurland.

Look at the results

grep -A 7 "Migration Rate"  trout_flat_out.txt trout_hier_out.txt
grep -A 7 "Inbreeding Coef" trout_flat_out.txt trout_hier_out.txt
  1. Under the flat prior, what happens to Lærdal and Fortun?
    AnswerBoth have a non-migrant fraction mii of 0.68, at the lower bound of 2/3, and F = 0.50, the prior: almost every fish sampled there is treated as the offspring of a migrant from Årdal (m ≈ 0.28 into each). This is the pooling artefact of Exercise 4, in a dataset with 26–39 fish per river. The published analysis reported natal-site fidelity of 0.689 for Lærdal and 0.680 for Fortun, the same signature; the three rivers involved are the least differentiated pairs (FST 0.02).
  2. What changes with -H, and how strong is the evidence for and against migration? 
    grep "for H" trout_hier_out.txt                # default table first, then the -B table
grep "cannot exceed" trout_hier_out.txt
    AnswerThe non-migrant fractions are now 0.94 (Lærdal), 0.79 (Årdal), 0.86 (Fortun) and 0.95 (Aurland), and F is 0.01–0.03 everywhere. Årdal receives the most migrants, about 0.09 each from Lærdal and Fortun. Eight routes have decisive evidence for migration (-B: log10 BF01 from −14 to −134). With 26–52 fish per river and K = 4 the ceiling is 9.7–18.3, so evidence against migration is possible too: Årdal → Lærdal and Årdal and Fortun → Aurland are "Strong for H0". Only Årdal → Fortun is unresolved: the two rivers are the least differentiated pair, and that rate also varies most between runs.
  3. Who are the first-generation migrants, and does an independent method agree? List every fish whose most probable ancestry is first-generation ([source,1]), then look up a fish in the telemetry file, which has the paper's own genetic assignment (column Pop.assign, from a discriminant analysis, DAPC) and the rivers where it was detected in the spawning season: 
    awk '/Individual:/{id=$2} /\[[0-9]+,1\]:/{for(i=1;i<=NF;i++){split($i,a,":"); if(a[2]>0.5) print id, a[1], a[2]}}' trout_hier_BA3indiv.txt
grep -E "^FishID|,AUR01," $D/trout_telemetry.csv | cut -d, -f2,7,9,13
    AnswerBA3 identifies 20 first-generation migrants with probability 0.9–1.0, most of them in the Årdal sample and most from Lærdal. 14 of them were tagged, and for 12 of those the paper's DAPC assignment names the same river of origin (the exceptions are ARD04 and ARD35). AUR01, for example, was caught in Aurland; BA3 says it is a first-generation migrant from Lærdal, DAPC assigns it to Lærdal, and it was detected in Aurland in three spawning seasons and in Lærdal in one. The telemetry records where adults went, which is not the same as where their parents came from, so it cannot check BA3's rates route by route; but it shows that adults move between these rivers often, as the many first-generation migrants imply.

Checklist for your own data 1 min

  • Use a current BA3 (with -B); rerun any Bayes factors from 3.4–3.5.
  • Thin to unlinked loci (for RAD data, one SNP per tag).
  • Use -c for speed, and -H when populations have few individuals.
  • Run at least two seeds, compare m and F, look at the trace, and try a longer run.
  • Red flags: m near 1/3 or mii near 2/3; F ≈ 0.5 with SD ≈ 0.29; one population "sending" to many others; reciprocal near-bound m between two samples; seeds that disagree.
  • If the Bayes-factor table prints < on a route that matters, rerun with -B.
  • Migration is easier to detect than to exclude: one clear migrant gives decisive evidence for migration, but evidence for its absence is capped by the number of individuals sampled.
  • Test routes with the Bayes factor, and check its ceiling (ni + K − 1)/(K − 1) in the notes under the table.
  • For more power, sample more individuals per population before typing more loci.
